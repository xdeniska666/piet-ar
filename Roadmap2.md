# MVP Roadmap: Project VisionID (The "Fast-Track" Edition)

Этот план сфокусирован на создании рабочего AR-прототипа (MVP) за минимальное время. Мы используем стандарты индустрии, чтобы не тратить время на "изобретение велосипеда".

## Фаза 1: CV Pipeline (Детекция)
Цель: Научить браузер "видеть" маркер и выдавать его координаты.
- [ ] **OpenCV.js Setup:** Подключение библиотеки через CDN.
- [ ] **Video Stream:** Захват потока камеры через `navigator.mediaDevices.getUserMedia`.
- [ ] **ArUco Detector:** Реализация `cv2.aruco.detectMarkers`.
- [ ] **Pose Estimation:** Вычисление `rvec` (поворот) и `tvec` (смещение).
- [ ] **Console Log:** Вывод координат в консоль. Убедиться, что они меняются плавно.

## Фаза 2: Matrix Bridge (Связка)
Цель: Превратить координаты OpenCV в 3D-пространство Three.js.
- [ ] **Fixed Parameters:** Использование фиксированных параметров камеры (FOV ~60°), без сложной калибровки на старте.
- [ ] **Matrix Conversion:** Функция конвертации `rvec/tvec` в `THREE.Matrix4`.
- [ ] **Sync:** Привязка матрицы 3D-объекта к матрице маркера.

## Фаза 3: Rendering (Визуализация)
Цель: Отрисовка модели поверх камеры.
- [ ] **Canvas Overlay:** Настройка полупрозрачного `canvas` Three.js поверх тега `<video>`.
- [ ] **Scene Setup:** Добавление света (`AmbientLight`, `DirectionalLight`).
- [ ] **Model Loading:** Реализация загрузчика GLB (с поддержкой Draco для легкого веса).

## Фаза 4: Backend API (Интеграция)
Цель: Подгрузка данных "на лету".
- [ ] **Fetch Logic:** Запрос к Go-API (Render) по ID маркера при первом обнаружении.
- [ ] **Dynamic Swap:** Логика выгрузки текущей модели и загрузки новой при смене ID.
- [ ] **Memory Management:** Простейшее кэширование объектов в памяти браузера.

## Фаза 5: Deployment (HTTPS)
Цель: Запуск в "боевом" режиме.
- [ ] **Vercel:** Деплой фронтенда (дает HTTPS автоматически).
- [ ] **Field Test:** Проверка на телефоне в реальных условиях освещения.
